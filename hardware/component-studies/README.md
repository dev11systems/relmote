# Relmote component studies

These documents compare **component classes and reference candidates**.

They are not procurement decisions or a frozen BOM.

The purpose is to prevent one convenient development board from accidentally defining the product.

## Evaluation dimensions

Candidates should be evaluated against:

- idle/typical/peak power;
- thermal behavior;
- physical envelope;
- Linux/mainline support where applicable;
- USB device/gadget capability;
- Wi-Fi/BLE integration;
- documentation;
- upstream longevity;
- openness;
- repairability;
- DIY accessibility;
- supply availability;
- cost;
- software burden.

A candidate can be excellent for All-in-One and wrong for Pocket.
